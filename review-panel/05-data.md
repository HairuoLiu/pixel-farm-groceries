# 评委 5 · 数据质量负责人 —— 实证审计报告

**项目**：像素农场 · 采购记（grocery-reminder-pixel）
**审查对象**：`data-100.js`（8 zones + 104 dishes）、`data.js`（旧 18 道回退数据）、`ingredient-icons.js`（`PXIcon.ING_ICON`）、`app.js` 数据消费层
**方法**：Node 脚本真实加载数据后统计（只读，不改动任何数据文件）；所有数字经 `_05_verify.js` **独立二次复核**（不复用前两个脚本的中间产物）

复现命令：

```bash
node review-panel/_05_data_audit.js    # 基础统计 → _05_stats.json
node review-panel/_05_data_audit2.js   # 图标覆盖 / 主料缺失 / optional 可信度 / tags 冗余
node review-panel/_05_verify.js        # 独立交叉复核（本报告数字以此为准）
```

## 一句话结论

> **工程卫生满分，内容质量不及格。**
> 104 道菜没有一条脏数据：0 重复 id、0 非法 zone、0 菜品内 emoji、122 种食材 **100%** 命中像素图标、同名食材跨分区冲突 0。
> 但数据有明显「规则批量生成」的痕迹 —— **104/104 道菜的 type/cuisine 与 `deriveType`/`deriveCuisine` 完全一致（100%）**，说明标注不是人工审过的，规则一错数据就跟着错：手撕包菜被正则里的「包」误判成主食、蒜蓉粉丝蒸虾被「粉」误判成主食。
> 更致命的是 **61 条食材漏写 `optional` 字段**，而 `app.js:260` 用 `optional: !!it.optional` 把 `undefined` 当成「必买」，勾一次「火锅」会往购物车一次性塞 18 项。
